# iXBRL Grounded Q&A: public demo

A web layer on top of the dissertation pipeline. `src/` (parser, fact store, C3 retrieval, the logged provider clients) is reused **unchanged**. Everything new is in `webapp/`.

```
webapp/
  __init__.py     routes, session handling, request guards
  answering.py    structured answers: cite IDs -> server verifies -> card JSON
  overview.py     filing overview + headline figures (no LLM)
  formatting.py   £4.812bn / 23.6p / "52 weeks ended 1 March 2025"
  ingest.py       hardened upload (filename, zip-slip, zip-bomb, parse gate)
  security.py     rate limits, quotas, access codes, spend cap, CSP headers
  sessions.py     one fact store per visitor, auto-deleted
  llm.py          wraps LoggedClient / LoggedOpenAIClient, meters spend
  make_code.py    generate Claude access codes
  templates/ static/
wsgi.py  gunicorn.conf.py  render.yaml  requirements-web.txt  .env.example
tests/            17 unit tests (stubbed src) + smoke_real.py (real src)
samples/          put 1–3 small public filings here -> "Try a sample" buttons
```

---

## 1. Merge into your repo

Copy `webapp/`, `tests/`, `samples/`, `wsgi.py`, `gunicorn.conf.py`, `render.yaml`, `requirements-web.txt`, `.env.example` and `.gitignore` into the repo root, next to `src/`. Leave your original `app.py` as it is for local research use.

Then run the adapter check against your **real** `src/` (no API calls):

```bash
python tests/smoke_real.py data/raw/<some_filing>.xhtml
python -m pytest -q tests
```

`smoke_real.py` prints five checks. Fix anything it flags before deploying. The key ones:
- **fact_id on retrieved rows.** The card reads the value from the cited `fact_id`.
- **XXE: safe.** If it says LEAKED, change the parser to use
  `etree.XMLParser(resolve_entities=False, no_network=True, huge_tree=True)`.

## 2. Protect the API keys (before anything goes public)

| Check | How |
|---|---|
| Keys never committed | `git log -p --all \| grep -nE "sk-(proj-\|ant-)?[A-Za-z0-9_-]{20,}"`. If anything matches, **rotate that key now**. Deleting the commit is not enough. |
| `.env` ignored | `git check-ignore .env` should print `.env` |
| Separate keys for the demo | OpenAI: new **Project** → project key, monthly budget (e.g. $5), allow only `gpt-5.6-terra`. Anthropic: new **Workspace** → key + workspace spend limit. The research keys stay private. |
| Keys only on the server | Set them in Render → Environment. The browser only ever talks to your Flask server. |
| Debug off | Production runs under gunicorn. `app.run(debug=True)` is never used. |

What stops abuse, in order: burst rate limit per IP → 10 questions/session → 20/IP/day → access code for Claude (per-code allowance) → **global cap of 300 questions and $2/day** → provider budgets. Counters are held in memory and reset on redeploy. The global cap and provider budgets still bound the worst case.

## 3. Deploy on Render (free)

1. Push the repo to GitHub.
2. Render → **New + → Blueprint** → select the repo. It reads `render.yaml`.
3. When asked, fill in the `sync: false` secrets:
   - `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`: the demo keys from step 2
   - `ACCESS_CODES`: see step 4
   - `CONTACT_LINKEDIN`: your profile URL
4. Deploy. Check `https://<name>.onrender.com/healthz` → `{"ok": true}`.

`SECRET_KEY` is generated by Render. The app refuses to start in production without one. Python is pinned to 3.12 because lxml 5.2.2 and pandas 2.2.2 have no wheels for 3.13+ (Appendix J).

**Free-tier behaviour to expect:**
- The service sleeps after 15 min idle, and the first visit then takes about a minute. Before a viva or interview demo, open the link a minute early.
- RAM is small. Parsing is limited to one filing at a time. If very large FTSE filings run out of memory, lower `MAX_UPLOAD_MB` or move to the Starter plan.
- The disk is ephemeral. That suits the promise that uploads are deleted.

## 4. Access codes for Claude

```bash
python -m webapp.make_code 25           # random code, 25 questions
python -m webapp.make_code 50 VIVA-2026 # chosen code
```

Send the **plain code** to the person. Append the printed **hash:quota** to `ACCESS_CODES` on Render, comma-separated, and save (Render redeploys). Only hashes are stored on the server. To revoke a code, delete its entry.

## 5. Sample filings

Put 1–3 **small** public filings in `samples/` (an FRS 102 filing of about 200 KB loads instantly). Filenames become button labels, e.g. `UK_Stone_Imports_FY2025.xhtml`. Each sample is parsed once, then copied per visitor. Use filings from the public register only. They are OGL v3.0.

## 6. How an answer is verified

The model gets the C3 evidence with IDs (`[F1577]`, `[N522]`) and must reply with JSON:

```json
{"answer_type":"fact|computation|narrative|not_found","fact_ids":["F1577"],
 "operation":"difference","narrative_id":"N522","quote":"…","summary":"…"}
```

| Case | Server does | Badge |
|---|---|---|
| fact | reads value/unit/period/dimensions from the cited row | Matched to tagged fact |
| computation | does the arithmetic itself from the two cited rows | Computed from tagged facts |
| narrative | checks that the quote appears verbatim in the cited text | Quote found in filing |
| invalid ID, bad JSON, fake quote | shows the summary only | Not verified: check the filing |
| not_found | honest abstention | Not in tagged data |

This removes transcription and arithmetic errors, but not **selection** errors: the model can still cite the wrong fact, such as a comparative year or the wrong dimension. That's why every card shows the period, dimension and "Other tagged values", and why the site says the demo is not the benchmarked condition.

Narrative excerpts now use keyword-density windows over the whole disclosure rather than the first 1,500 characters. This is the "future work" direction from decision log 2026-08-24. It hasn't been benchmarked, so don't claim it fixes Q018/Q036/Q054 until you've re-run them.
